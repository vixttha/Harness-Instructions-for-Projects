# HIP checkpoint queue

One active checkpoint: Head → Worker → Validate → Internal Auditor → Head. Failed or incomplete verification returns to Worker. Record exact base, fix, candidate, tested checkout, job/run attempt, merge and disposition separately. No paid runners, required branch protection or new meta-prompts without owner approval.

| Order | Scope | Gate | State |
|---|---|---|---|
| 1 | v0.0.0.1 foundation | Approved slogans, exact license, public CI, readback and acceptance | Worker, issue #1 |
| 2 | Preserve Instructions HQ | Every blob matches pinned source; retain MIT and lineage; preserve original branch | Inventory prepared; migration pending |
| 3 | Install VIB | Latest genuinely qualified immutable package; dedicated branch; exact install tests | Pending qualification |
| 4 | Veraphify | Pin verified source, graph import/verify/lookup | Pending |
| 5 | Provenistem | Empty portable starter, no borrowed catalogs | Pending |
| 6 | Brand Identity | Approved slogans, provisional name; visual and legal gates separate | Pending installation |
| 7 | README HQ | Qualified version, HIP-specific README, actual evidence | Pending |
| 8 | Lydite | Positive/negative cases and exact runner receipts | Pending |
| 9 | Reusable toolkit | Create/audit/refine/validate/version/maintain; mechanical vs behavioral checks separate | Pending |
| 10 | ChatGPT Projects pilot | Owner-approved settings installation, exact readback, independent fresh chats, rollback | Pending |

Reserve permanent versions only after canonical issue creation. Integrations optional and separate. Never copy another adopter's live state. No release or merge authorization inferred from test success.
